# 부.읽.카 설계 문서 (초안)

> 작성일: 2026-11-09 · 상태: 작업본 · 대상: Pleos Connect 차량용 앱
> 프로젝트 이름 `BuReadCar`는 임시 이름이다.

표기: ✅ 직접 또는 공식 자료로 확인 · ⚠️ 일부만 확인, 구현 전 명세 확인 필요 · ❌ 찾지 못함

## 1. 개요

부.읽.카(부동산 읽어주는 카)는 출퇴근 경로에 있는 지역의 부동산 소식을 음성으로 읽어 주는 앱이다. 사용자는 요일마다 듣고 싶은 소식을 최대 2개 골라 둔다. 운전 중에는 화면을 보거나 조작하지 않고 듣기만 한다.

**대표 시나리오**

1. 월요일 아침, 운전자가 회사로 내비 안내를 시작한다.
2. 앱이 경로가 지나는 시군구를 구하고, 월요일에 배치된 카테고리의 소식을 준비한다.
3. "오늘은 분양·청약 소식입니다. 경로 순서대로 성남시 분당구부터 전해 드릴게요." 하고 읽기 시작한다.
4. 내비 안내 음성이 나오면 브리핑이 잠시 멈췄다가 이어진다.

## 2. 기능 요구사항

### 2.1 듣기 범위

| 모드 | 지역을 정하는 방법 | 비고 |
| --- | --- | --- |
| **경로 안 소식** (기본값) | 지금 안내 중인 내비 경로 | 안내가 없으면 현재 위치의 시군구로 대체 |
| **저장된 경로 소식** | 사용자가 저장한 경로(집→회사 등) | 내비 안내 없이도 재생 가능. 실제 주행 경로와 달라도 저장 경로 기준 |

저장 경로는 차량 내비의 즐겨찾기로 만든다. SDK에 `HOME`, `OFFICE` 유형이 있어 집→회사 경로를 기본으로 제안할 수 있다. ✅

### 2.2 요일 편성표

- 월~금 각 요일에 칸 2개가 있고, 카테고리 박스 10개를 끌어다 놓는다.
- 한 칸 또는 두 칸을 비워도 된다. 모두 빈 요일은 자동 재생하지 않는다.
- 같은 카테고리를 여러 요일에 놓을 수 있다. 같은 요일에 중복해서 놓을 수는 없다.
- 재생 순서는 위 칸, 아래 칸 순이다.
- 주말은 편성이 없다. 앱을 열어 카테고리를 직접 고르면 들을 수 있다.

**기본 편성** (첫 실행 시 제안, 자유롭게 변경)

1번 칸(1부)에는 소식이 가장 많은 다섯 카테고리를, 2번 칸(2부)에는 소식이 적은 카테고리를 짝지어 요일별 분량을 맞춘다.

| 요일 | 1번 칸 | 2번 칸 |
| --- | --- | --- |
| 월 | 분양·청약 | 정책·규제 |
| 화 | 실거래가·신고가 | 미분양·입주물량 |
| 수 | 전월세 시세 | 재건축·재개발 |
| 목 | 교통 호재 | 금리·대출 |
| 금 | 주택가격지수·증감률 | 개발 호재 |

소식 양 측정 (2026-11-14, 분당구·수정구·강남구·서초구 기준)

| 카테고리 | 양 |
| --- | --- |
| 전월세 시세 | 구별 월 300~1,300건 계약 (9~10월) |
| 실거래가·신고가 | 구별 월 70~230건 매매 (9~10월) |
| 주택가격지수·증감률 | 모든 구, 매주 목요일 갱신 |
| 분양·청약 | 경기 주 0~10건, 서울 주 0~1건 접수 진행 |
| 교통 호재 | 국토부 보도자료 주 3건 안팎 |
| 정책·규제 / 개발 호재 / 미분양·입주물량 / 재건축·재개발 | 보도자료 주 2.7 / 1.3 / 0.7 / 0.3건 |
| 금리·대출 | 전국 1건, 월 1회 갱신 |

### 2.3 재생

- **시작:** 경로가 확정되면 자동 시작한다. 설정에서 "버튼을 눌러야 시작"으로 바꿀 수 있다.
- **조작:** 재생/일시정지, 다음 소식, 처음부터. 스티어링 휠 미디어 버튼 지원은 구현 때 확인한다.
- **길이:** 남은 주행 시간 안에 끝나도록 소식 수를 줄인다(5.2).
- **중복 방지:** 같은 소식은 다시 읽지 않는다. 다만 퇴근길에는 "아침과 같은 내용"임을 알리고 다시 들을 수 있게 한다.
- **도착:** 목적지에 도착하면 현재 문장까지 읽고 멈춘다. 남은 소식은 앱에 표시한다.

**발급이 필요한 키:** 공공데이터포털(카테고리 1, 3, 4), R-ONE(2), ECOS(5), 지역 변환용 V-World 키(4장).

**보도자료 카테고리 (6~10):** 국토교통부 보도자료 게시판에서 최근 31일 글을 읽어 제목 키워드로 카테고리를 나눈다. 제목에 경로의 시군구 이름이 있으면 그 지역 소식, 시도 이름이나 "수도권"이 있으면 그 지역 소식으로 읽는다. 둘 다 없으면 "경로 지역 소식이 없어 전국 소식으로 대신 전해 드려요"라고 말한 뒤 최신 전국 소식 2건을 읽는다. 장관 동정, 해명, 기념식처럼 장소나 제도에 관한 소식이 아닌 글은 뺀다. 국토교통부 보도자료는 공공누리에 따라 누구나 이용할 수 있다.

**데이터 해석 시 주의**

- 실거래는 계약 후 신고까지 최대 30일 걸릴 수 있어, 이번 달 거래량은 항상 적게 보인다. "이번 달 거래량 급감" 같은 비교를 만들면 안 된다.
- 해제(취소)된 거래도 응답에 포함되므로 제외한다.
- 신고가는 API가 알려 주지 않는다. 단지+면적별 과거 최고가와 비교해야 하며, "최근 N개월 내 최고가"로 범위를 명시한다.
- 주간 지수는 목요일 발표로 알려져 있다(비공식 자료, 공식 일정 확인 필요). 화요일 편성이면 지난주 발표치를 읽는 셈이므로 기준일을 함께 읽는다.

### 3.0 R-ONE 확인 내용 (2026-11-09)

- Open API는 통계 목록, 세부 항목, 조회 조건 3종이며, 통계코드 검색에 통계표 665건이 등록되어 있다.
- 주간아파트동향 통계표: `T244183132827305` 매매가격지수, `T242143133025413` 규모별, `T247243133036080` 연령별. 항목 `10001`은 지수다.
- 호출 검증(2026-11-09): `SttsApiTblItm.do`로 지역 분류 237개, `SttsApiTblData.do`(`DTACYCLE_CD=WK`, `START_WRTTIME=202644`)로 주간 값 조회에 성공했다. 강남구, 분당구, 수원시 등 시군구 분류가 있다.
- R-ONE 지역 ID(`CLS_ID`, 예: 50224)는 법정동코드가 아니다. `CLS_FULLNM`(예: `경북>포항시`)과 V-World 시군구 이름을 잇는 매핑표가 필요하다. 시 단위와 일반구 단위가 섞여 있으므로 일반구가 없으면 상위 시로 대체한다.
- 전주 대비 증감률은 이 통계표의 항목에 지수만 보이므로, 별도 통계표가 없으면 지수로 직접 계산한다.
- 메인 화면의 월간 지역 지도는 시도에서 시군구까지 볼 수 있다고 안내한다. 공동주택 실거래가격지수, 상업용 임대동향, 오피스텔 동향은 시군구 선택이 불가하다.
- 지가변동률에 지하철 역세권, 고속철도 역세권, 3기신도시 등 보조지수가 있어 호재 카테고리의 정량 소재로 쓸 수 있다.

### 3.1 KB부동산 데이터허브 검토 (2026-11-09)

[KB부동산 데이터허브](https://data.kbland.kr/)에서 메뉴 구성과 미분양 화면을 확인했다.

| 관련 카테고리 | 데이터허브 메뉴 | 확인 내용 |
| --- | --- | --- |
| 미분양·입주물량 | 공공통계 > 미분양, 주택공급 | 미분양은 월별 추이와 시도별 지도 제공. 주택공급은 분양, 입주물량, 인허가, 청약통장 현황으로 안내됨 |
| 주택가격지수·증감률 | KB통계 > 주택가격동향조사, 주간 KB주택가격동향 | 주간 자료가 2026-11-06자로 게시됨 |
| 실거래가·신고가 | 실거래가 랭킹 | 메뉴 존재, 내용 미확인 |
| 정책·규제 | 공공통계 > 정부정책 | 시기별 정책 내용으로 안내됨, 화면 미확인 |
| 신규 후보 | 부동산 심리지수, 월간선도아파트, 소득대비주택가격 | 샘플 대신 쓸 수 있는 KB 고유 지표 |

**활용 방침:** 데이터 구성과 원고 소재를 잡는 참고 자료로 쓴다. 공개 API와 앱 내 재사용 조건을 찾지 못했으므로, 허가 없이 웹 내부 API를 호출하거나 화면을 수집해 앱에 넣지 않는다. 앱에 실제로 넣으려면 KB 측 이용 조건 확인 또는 제휴가 먼저다.

**미분양 소스:** 데이터허브가 "공공통계"로 분류한 만큼 원 출처 공공 통계를 찾아 연동하는 것이 우선이다. 시군구 단위 제공 여부는 미확인이다.

## 4. 경로에서 지역 구하기

### 4.1 SDK 조사 결과 (NaviHelper 3.0.5, navi-data 3.0.4)

| 필요한 정보 | SDK | 결과 |
| --- | --- | --- |
| 현재 위치 | `getCurrentLocationInfo` → 위도, 경도, 주소 | ✅ |
| 목적지 | `getDestinationInfo` → 위도, 경도, 주소, 남은 거리/시간 | ✅ |
| 경유지 | `getWaypointInfo` | ✅ |
| 즐겨찾기 | `getBookmarkInfo` → `HOME`, `OFFICE`, `DEFAULT` 등 | ✅ |
| 안내 시작/종료/재탐색 | `onRouteStarted`, `onRouteEnded`, `onReRouteEnded` 등 | ✅ |
| **경로 선형(좌표열)** | 공개 데이터 클래스에 없음 | ❌ |
| 경로 위 지점 | `TripSummary.routePoints` (좌표, `ratioOnRoute`) | ⚠️ 어떤 지점이 얼마나 촘촘히 오는지 미검증 |

**제약:** SDK가 경로 전체 좌표를 주지 않으므로, 출발 전에 "지나는 시군구 전체"를 알 수는 없다. 대신 현대 내비가 주는 출발지, 경유지, 목적지, 주행 중 현재 위치만으로 1차 기능을 만든다. 외부 길찾기 API는 쓰지 않는다.

### 4.2 처리 방법

```
출발지(현재 위치), 경유지, 목적지 + 주행 중 약 2km마다 현재 위치
  → 좌표 → 법정동코드 변환 (V-World getAddress, type=PARCEL의 level4LC)
  → 앞 5자리(시군구)만 남기고 경로 순서대로 중복 제거
  → RegionPath: [성남시 분당구, 서초구, 강남구]
```

**대체 순서**

1. 출발 시 출발지, 경유지, 목적지의 시군구로 재생 목록을 만든다 (기본).
2. 주행 중 새 시군구에 들어가면 그 지역 소식을 받아 다음 순서에 끼워 넣는다 ("지금 지나는 {시군구} 소식입니다").
3. `requestTrip`의 `TripSummary.routePoints`에 경로 중간 좌표가 충분히 오면 출발 전 목록에 반영한다 (에뮬레이터 확인 후 결정).

저장 경로 모드는 내비 안내가 없을 수 있으므로 출발지, 경유지, 도착지 시군구만 쓴다. 출발 전에 경로 전체 지역이 꼭 필요해지면 그때 외부 길찾기 API를 추가한다.

**V-World 사용 조건:** 공식 문서상 일일 요청은 무제한이지만, 결과를 별도 저장장치나 DB에 저장할 수 없고 실시간으로만 써야 한다. 그래서 변환 결과를 캐시하지 않고 경로마다 실시간 호출한다. 저장 경로도 출발지와 도착지만 저장하고 지역은 매번 구한다. ✅ 2026-11-09 APP 유형 키로 호출 성공. 성남시 수정구 41131, 분당구 41135, 서초구 11650, 수원시 팔달구 41115로, `type=PARCEL`의 `level4LC` 앞 5자리를 `LAWD_CD`로 쓸 수 있는 형식임을 확인했다. 일반구가 있는 시도 `level2`에 "성남시 수정구"처럼 합쳐서 오고 `level3`는 비어 있다. ✅ V-World의 41135를 실거래가 API에 그대로 넣어 분당구 거래를 받았다.
**지역 선택 규칙:** 잠깐 스치는 시군구까지 넣으면 관심 없는 소식이 많아진다. 고속도로 통과 구간은 선호도를 낮추고, 우선순위를 **목적지 → 출발지 → 경로 내 체류 거리가 긴 순**으로 둔다. 읽는 순서는 경로 순서를 따른다.

> 카카오맵 API 무료 쿼터 정책이 2026-07-21부터 바뀌어, 개발자 계정의 첫 앱에만 제공된다는 공식 안내가 있다. 길찾기 API는 이용 조건을 따로 확인해야 한다.

### 4.3 에뮬레이터 시연

에뮬레이터의 위치는 고정이고 콘솔로 주행해도 내비 값이 변하지 않는다. 그래서 앱에 시연 주행을 두어 경로를 시간 흐름에 따라 재생한다.

- 촬영을 위해 앱의 오늘을 월요일로 고정해 두었다(`RadioViewModel.BROADCAST_DAY`, null이면 달력을 따른다). 홈 화면, 오늘 방송, 시연 주행이 모두 월요일 편성을 쓴다.
- 경로는 내비 안내 중이면 내비 경로, 아니면 미리 정한 하남(미사역)→강동(고덕역)→송파(잠실역)→강남(삼성역) 경로를 쓴다. 출발지에서 목적지까지 약 3km마다 지점을 찍어 지나가는 지역의 소식을 끼워 넣는다.
- 좌표가 0,0인 즐겨찾기와 지점은 경로로 쓰지 않는다.

## 5. 브리핑 생성

### 5.1 템플릿 방식 (LLM 미사용)

숫자는 틀리면 안 되고 응답 시간과 비용도 일정해야 하므로, 1차는 정형 데이터를 템플릿으로 문장화한다. LLM 요약은 뉴스 기반 카테고리를 실데이터로 전환할 때 검토한다.

읽기 좋게 변환한다: `153000`(만원) → "15억 3천만 원", `84.97㎡` → "전용 84제곱미터", `-0.03` → "0.03퍼센트 하락".

**구성**

```
여는 말    오늘은 {요일} {카테고리} 소식입니다. {기준일} 기준이에요.
지역 1     {시군구}입니다. {소식 1}. {소식 2}.
지역 2     다음은 {시군구}입니다. ...
맺음말     출처는 {기관}입니다. 다음은 {2번 칸 카테고리}입니다.
```

**템플릿 예시**

- 분양·청약: `{단지명}이 {모집공고일}에 공고됐고, 일반공급 청약은 {접수일}입니다. 공급 규모는 {세대수}세대입니다.`
- 지수: `{시군구} 아파트 매매가격은 전주보다 {변동률} {상승|하락}했습니다. {n}주 연속 {상승|하락}입니다.`
- 실거래: `{법정동} {단지명} 전용 {면적}제곱미터가 {금액}에 거래됐습니다. 최근 {N}개월 중 가장 높은 가격입니다.`

**소식 원칙 (2026-11-14)**

1. **금주 → 차주:** 이번 주 소식을 먼저 읽고, 다음 주 일정이 이미 나와 있으면 이어서 읽는다. 분양·청약은 이번 주에 접수 중이거나 시작하는 공고, 다음 주에 접수를 시작하는 공고를 각각 최대 2건 읽는다. 그 뒤의 공고는 읽지 않는다.
2. **이전 기간과 비교:** 비교할 숫자가 있으면 증감을 함께 읽는다.
   - 주택가격지수: 전주 대비 변동률과 연속 상승·하락 주 수
   - 실거래가: 제곱미터당 평균 거래가의 전월 대비 변동률 (두 달 모두 5건 이상일 때)
   - 전월세: 전세 보증금 제곱미터당 평균의 전월 대비 변동률 (두 달 모두 5건 이상일 때)
   - 금리: 전월 대비 퍼센트포인트 변화
   - 실거래 신고는 계약 후 30일까지 들어오므로 건수는 비교하지 않고 "지금까지 N건"으로만 읽는다.
3. **끝맺음 정리:** 방송 끝에 "끝으로 오늘의 핵심을 정리해 드립니다"로 카테고리마다 핵심 한 문장을 다시 읽는다. 핵심 문장은 소식마다 미리 만들어 두고, 도착지에 가까운 지역의 것을 고른다. 정리에 드는 시간은 시간 맞추기 전에 먼저 떼어 둔다.
4. **본문은 자세히, 정리는 짧게:** 소식마다 숫자와 맥락을 함께 읽는다. 예를 들어 청약은 위치·시공사·순위별 접수일·당첨자 발표일·분양가·입주 예정을, 실거래는 직거래·해제·최고가 층·거래 많은 단지·84제곱미터 평균을, 보도자료는 본문 첫 문장들을 읽는다. 끝맺음 정리만 한 문장씩 짧게 한다.
5. **말투:** 방송 문장은 모두 "~입니다/~합니다"로 끝낸다. 보도자료의 "~한다/~했다"는 바꿔 읽고, 제목은 "~ 소식입니다"로 감싼다. 화면 안내 문구는 "~해요"를 그대로 쓴다.
6. **시작 안내:** 어느 경로 기준으로 어느 지역을 어떤 순서로 읽는지 말한다. 예) "내비게이션 경로를 따라 성남시 분당구와 강남구 순서로 전해 드립니다."

### 5.2 시간에 맞추기

- 도착까지 남은 시간(`remainTime`)에서 여유분을 뺀 시간을 재생 예산으로 한다.
- 소식별 예상 길이는 글자 수로 추정하고, 실제 TTS 속도를 측정해 보정한다.
- 예산을 두 카테고리에 절반씩 나눈다. 한쪽이 짧게 끝나면 남은 시간은 다른 쪽에 준다.
- 예산이 부족하면 4.2의 우선순위가 낮은 지역부터 뺀다.

### 5.3 소식이 없을 때

1. 경로 시군구에 소식이 없으면 상위 시도 소식으로 넓히고, "경로 지역에는 새 소식이 없어 {시도} 소식을 전합니다"라고 말한다.
2. 그래도 없으면 "이번 주 새 소식이 없습니다"라고 말하고 다음 칸으로 넘어간다.
3. API 실패 시 저장된 최근 데이터를 기준일과 함께 읽는다. 저장분도 없으면 해당 카테고리를 건너뛰고 이유를 짧게 알린다.

## 6. 음성과 오디오

- **TTS:** Pleos Connect SDK의 `TextToSpeech`를 쓴다. 텍스트를 보내면 합성 음성이 앱으로 돌아오는 구조다. ⚠️ 한국어 음색, 길이 제한, 오프라인 동작, 에뮬레이터 동작은 첫 구현에서 확인한다.
- **불러오기:** 한국부동산원 R-ONE은 요청마다 5~8초가 걸린다. 그래서 카테고리와 지역별 요청을 동시에 보내고, 앱을 켤 때 경로와 상관없는 목록(R-ONE 분류, 보도자료 목록)을 미리 받으며, 지수는 1시간 동안 다시 쓴다.
- **속도:** SDK 3.3.1에는 말하기 속도 설정이 없다. 문장마다 그 문장을 읽는 시간의 약 11%(0.3~1.2초)를 쉬어 전체가 0.9배 속도로 흐르게 한다. 시간 맞추기의 글자 수 추정도 같은 비율을 쓴다.
- **오디오 포커스:** Pleos Audio Focus Policy를 따른다. 공식 문서에서 정책 값을 코드에 고정하지 말라고 권장하므로 설정으로 분리한다.
- **내비 안내와 겹칠 때:** 소리를 낮춰 겹치게 하지 않고 브리핑을 일시정지한 뒤 현재 문장 처음부터 이어 읽는다. 숫자를 놓치면 소식의 의미가 없어지기 때문이다. 정책과 맞는지 Interaction Matrix로 확인한다.
- **전화, 미디어:** 포커스를 잃으면 멈춘다. 음악 앱에서 포커스를 가져올 때의 동작은 정책을 따른다.

## 8. 앱 구조

Kotlin + Jetpack Compose. 실제 SDK 구현과 시연용 구현을 인터페이스로 분리한다.

```
app/
  route/      RouteSource(Navi, Saved, Fake), RegionResolver
  schedule/   Category, WeeklySchedule, ScheduleRepository
  news/       NewsProvider(카테고리별 구현, Sample), NewsRepository
  briefing/   BriefingPlanner(지역, 시간 예산), ScriptComposer(템플릿)
  player/     BriefingPlayer(TTS, 오디오 포커스)
  ui/         Player, Schedule, Settings
```

```kotlin
enum class ListenMode { ON_ROUTE, SAVED_ROUTE }

data class Region(val lawdCode: String, val sido: String, val sigungu: String)
data class SavedRoute(val id: String, val name: String, val origin: Place, val destination: Place) // 지역은 V-World 조건상 저장하지 않음
data class WeeklySchedule(val slots: Map<DayOfWeek, List<Category>>) // 요일당 최대 2개

data class NewsItem(
    val id: String,
    val category: Category,
    val region: Region?,        // 전국 소식은 null
    val facts: Map<String, String>,
    val asOf: LocalDate,
    val source: String,
    val isSample: Boolean,
)

interface NewsProvider {
    val category: Category
    suspend fun fetch(regions: List<Region>, today: LocalDate): List<NewsItem>
}
```

**서버 없이 시작한다.** 1차 구현은 기기에서 공공 API를 직접 호출한다. 편성과 설정은 기기에 저장하지만, 소식 캐시는 아직 없어 API가 실패하면 해당 카테고리를 건너뛴다. 키는 `local.properties`에 두고 git에 올리지 않는다.

제품화할 때는 프록시 서버가 필요하다. APK에 들어간 키는 추출될 수 있고, 차량마다 같은 데이터를 호출하는 낭비가 있으며, 신고가 판정에 쓸 과거 데이터도 서버에 쌓는 편이 낫다. `NewsProvider`만 바꾸면 전환되도록 설계한다.

**미리 받기:** 출발 시점에 처음 호출하면 재생이 늦어진다. 저장 경로의 지역은 전날 또는 앱 실행 시 받아 두고, 경로가 바뀌면 부족한 지역만 추가로 받는다.

## 9. 법적 고지와 안내

- 앱과 첫 재생에 "참고용 정보이며 투자 권유가 아닙니다"를 안내한다.
- 음성에서 "지금이 기회" 같은 평가나 매수·매도 권유를 하지 않는다. 사실, 수치, 기준일, 출처만 읽는다.
- "호재"는 사업 단계(계획, 착공, 개통 예정)를 함께 말한다. 계획 단계 사업을 확정처럼 들리게 하면 안 된다.
- 뉴스 본문을 그대로 읽는 것은 저작권 문제가 있다. 실데이터 전환 시 뉴스 사용 범위를 먼저 검토한다.
- 공공 API별 이용 조건(출처 표시, 상업적 이용)을 키 신청 시 확인한다.
- 위치와 경로는 기기에 저장하고, 지역 변환 등 외부 호출에는 필요한 좌표만 보낸다.

## 10. 구현 순서

| 단계 | 내용 | 완료 기준 |
| --- | --- | --- |
| 0 | 위험 검증 | TTS 재생, `TripSummary.routePoints` 값, 길찾기 API 조건 확인 |
| 1 | 앱 뼈대 | 편성표 편집과 저장, 샘플 데이터로 재생 |
| 2 | 경로 연동 | 두 모드 모두 `RegionPath` 생성, 시연 경로 재생 |
| 3 | 실데이터 | 실거래 → 지수 → 청약 → 전월세 → 금리 순서로 연동 |
| 4 | 음성 완성도 | 시간 예산, 포커스, 내비 안내와의 일시정지 |
| 5 | 시연 준비 | API 실패 대비 저장 데이터, 시연 시나리오 |

## 11. 열린 질문

1. **저장 경로의 정의:** 출발지와 도착지 한 쌍으로 충분한가, 아니면 경유 도로까지 고정해야 하는가? (초안: 한 쌍)
2. **퇴근길:** 같은 요일의 퇴근길에도 같은 편성을 들을 것인가? (초안: 같은 편성, 새 소식 우선)
3. **"경로 안"의 범위:** 지나는 시군구 전체인가, 출발지와 도착지 중심인가? (초안: 전체에서 도착지 우선)
4. **공모전 일정과 심사 기준:** 실데이터 범위와 시연 방식을 정하는 데 필요하다.
