> 처음 작성: 2026-11-09 · 갱신: 2026-11-15 (`feature/app-v1` 코드 기준) · 대상: Pleos Connect 차량용 앱
> 프로젝트 이름 `BuReadCar`는 임시 이름이다.

표기: ✅ 구현됨 또는 공식 자료로 확인 · ⚠️ 일부만 확인 · ❌ 미구현 또는 찾지 못함

## 1. 개요

부.읽.카(부동산 읽어주는 카)는 출퇴근 경로에 있는 지역의 부동산 소식을 음성으로 읽어 주는 앱이다. 사용자는 요일마다 듣고 싶은 소식을 최대 2개 골라 둔다. 운전 중에는 화면을 보거나 조작하지 않고 듣기만 한다.

**대표 시나리오**

1. 월요일 아침, 운전자가 회사로 내비 안내를 시작한다.
2. 앱이 출발지, 경유지, 목적지의 시군구를 구하고, 월요일에 편성된 카테고리의 소식을 모은다.
3. "부.읽.카입니다. 참고용 정보이며 투자 권유가 아닙니다. 오늘은 월요일 분양·청약과 정책·규제 소식입니다. 내비게이션 경로를 따라 성남 분당구와 서울 강남구 순서로 전해 드립니다." 하고 읽기 시작한다.
4. 지역마다 1부와 2부를 이어서 읽는다. 주행 중 새 시군구에 들어서면 그 지역 소식을 끼워 넣는다.
5. 내비 안내 음성이 나오면 방송이 멈췄다가 그 문장 처음부터 이어진다.
6. 끝으로 카테고리마다 핵심을 한 문장씩 정리하고 마친다.

## 2. 기능 요구사항

### 2.1 듣기 범위

| 모드 | 지역을 정하는 방법 | 주행 중 지역 추가 |
| --- | --- | --- |
| **내 경로 지역** (기본값) | 내비의 현재 위치, 경유지, 목적지. 목적지가 없으면 현재 위치의 시군구만 | ✅ 있음 |
| **저장된 경로** | 저장된 경로의 출발지와 도착지 | 없음 |

- 저장된 경로는 두 가지다. 하나는 기본 예시 경로 "예시: 미사역 → 삼성역"이고, 다른 하나는 내비 즐겨찾기의 `HOME`, `OFFICE`로 자동으로 만드는 "집 → 회사"다. 설정에서 둘 중 하나를 고른다. 직접 경로를 추가하는 화면은 없다.
- 좌표가 0,0인 즐겨찾기와 지점은 경로로 쓰지 않는다. 쓸 수 있는 저장 경로가 없으면 예시 경로를 보여 준다.

### 2.2 요일 편성표

- 월~금 각 요일에 칸 2개(1부, 2부)가 있고, 카테고리 박스 10개를 끌어다 놓는다.
- 칸끼리 끌면 자리를 바꾸고, 칸 밖으로 끌어내면 뺀다.
- 한 칸 또는 두 칸을 비워도 된다. 같은 카테고리를 여러 요일에 놓을 수 있지만, 같은 요일에 두 번 놓을 수는 없다("같은 요일에 같은 소식은 넣을 수 없어요").
- 주말은 편성이 없다. 홈에 카테고리 10개가 나오고, 하나를 누르면 그 카테고리만 듣는다.
- 편성은 기기에 저장한다(`SettingsStore`).

**기본 편성** (첫 실행 시 제안, 자유롭게 변경)

1부에는 소식이 가장 많은 다섯 카테고리를, 2부에는 소식이 적은 카테고리를 짝지어 요일별 분량을 맞춘다. 주택가격지수는 R-ONE이 목요일에 발표하므로 금요일에 둔다.

| 요일 | 1부 | 2부 |
| --- | --- | --- |
| 월 | 분양·청약 | 정책·규제 |
| 화 | 실거래가·신고가 | 미분양·입주물량 |
| 수 | 전월세 시세 | 재건축·재개발 |
| 목 | 교통 호재 | 금리·대출 |
| 금 | 주택가격지수·증감률 | 개발 호재 |

소식 양 측정 (2026-11-14, 분당구·수정구·강남구·서초구 기준)

| 카테고리 | 양 |
| --- | --- |
| 전월세 시세 | 구별 월 300~1,300건 계약 (9~10월) |
| 실거래가·신고가 | 구별 월 70~230건 매매 (9~10월) |
| 주택가격지수·증감률 | 모든 구, 매주 목요일 갱신 |
| 분양·청약 | 경기 주 0~10건, 서울 주 0~1건 접수 진행 |
| 교통 호재 | 국토부 보도자료 주 3건 안팎 |
| 정책·규제 / 개발 호재 / 미분양·입주물량 / 재건축·재개발 | 보도자료 주 2.7 / 1.3 / 0.7 / 0.3건 |
| 금리·대출 | 전국 1건, 월 1회 갱신 |

**요일:** 앱의 오늘은 달력의 요일을 따른다. 시연 영상을 찍을 때는 `RadioViewModel.kt`의 `BROADCAST_DAY`에 요일(예: `DayOfWeek.MONDAY`)을 넣어 그 요일로 고정할 수 있다. 고정하면 주말 화면은 나오지 않는다.

### 2.3 재생

- **시작:** "오늘 방송 듣기"를 누르거나, 내비가 경로 안내를 시작하면 자동으로 시작한다. 자동 시작은 설정에서 끌 수 있다. 앱이 실행 중일 때만 내비 이벤트를 받는다.
- **자동 시작 조건:** 위치 이용에 동의했고, 방송을 준비하거나 재생하는 중이 아니며, 시연 주행 뒤가 아닐 때만 시작한다. 내비가 경로를 다시 시작하거나 재탐색해도 듣던 방송을 처음부터 다시 틀지 않는다.
- **다른 오디오와 겹친 자동 시작:** 안내 시작 음성처럼 다른 소리가 나는 중이면 1초마다 확인하며 최대 30초 기다렸다가 시작한다. 기다리는 동안 버튼은 "일시정지"로 보이고, 누르면 대기를 취소한다. 30초가 지나도 소리가 계속되면 "끝난 뒤 재생을 눌러 주세요"라고 안내한다.
- **조작:** 재생/일시정지, 다음 소식, 처음부터, 끝내기. ❌ 스티어링 휠 미디어 버튼(MediaSession)은 아직 없다.
- **길이:** 남은 주행 시간 안에 끝나도록 소식 수를 줄인다(5.2).
- **도착:** 목적지 도착, 안내 종료, 안내 취소 이벤트가 오면 지금 문장까지 읽고 멈춘다. 경로를 편집하는 중에 오는 종료 이벤트로도 멈출 수 있다.
- ❌ **중복 방지:** 같은 소식을 다시 읽지 않는 기능과 퇴근길의 "아침과 같은 내용" 안내는 구현하지 않았다.

**보도자료 카테고리 (6~10):** 국토교통부 보도자료 게시판에서 최근 31일 글을 최대 10쪽까지 읽고, 제목 키워드로 카테고리를 나눈다. 목록을 못 읽으면 RSS의 최신 10건을 쓴다.

- 제목에 경로의 시군구 이름이 있으면 그 지역 소식으로, 시도 이름이나 "수도권"이 있으면 "경로가 지나는 {시도} 관련 소식을 전합니다"로 읽는다. 지역마다 최대 2건, 카테고리마다 최대 3묶음이다.
- 둘 다 없으면 "경로 지역 소식이 없어 전국 소식으로 대신 전해 드립니다"라고 말한 뒤 최신 전국 소식 2건을 읽는다.
- 장관 동정, 인사, 해명, 기념식, 박람회, 사고처럼 장소나 제도에 관한 소식이 아닌 글은 뺀다.
- 본문은 방송에서 읽을 글만 받는다. 상세 페이지에서 첨부 hwpx를 찾아 `Contents/section0.xml`의 문단을 읽는다. 인용문과 "다음과 같다" 문장은 빼고, "~했다"는 "~했습니다"로 바꾼다. 받지 못하면 제목만 읽는다.
- 국토교통부 보도자료는 공공누리에 따라 누구나 이용할 수 있다.

**데이터 해석 시 주의**

- 실거래는 계약 후 신고까지 최대 30일 걸려 이번 달 건수는 항상 적게 보인다. 그래서 이번 달은 읽지 않고, 건수는 비교 없이 "지금까지 N건"으로만 읽는다.
- 해제(취소)된 거래는 평균과 최고가 계산에서 뺀다.
- 평균의 전월 대비 변동은 두 달 모두 5건 이상일 때만 읽는다.
- 신고가는 API가 알려 주지 않는다. 지금은 조회한 달의 최고 거래만 읽고, 과거 전체 거래와 비교하는 역대 신고가 판정은 하지 않는다. 카테고리 이름은 그대로 둔다.
- 주간 지수는 "{날짜} 주간 기준"으로 기준일을 함께 읽는다.

### 3.0 R-ONE 확인 내용 (2026-11-09)

- Open API는 통계 목록, 세부 항목, 조회 조건 3종이며, 통계코드 검색에 통계표 665건이 등록되어 있다.
- 주간아파트동향 통계표: `T244183132827305` 매매가격지수, `T242143133025413` 규모별, `T247243133036080` 연령별. 항목 `10001`은 지수다.
- `SttsApiTblItm.do`로 지역 분류 237개, `SttsApiTblData.do`(`DTACYCLE_CD=WK`)로 주간 값을 받는다. 강남구, 분당구, 수원시 등 시군구 분류가 있다.
- R-ONE 지역 ID(`CLS_ID`)는 법정동코드가 아니다. 앱은 매핑표 없이 분류 전체 이름(예: `경기>성남시>분당구`)을 V-World 시군구 이름과 맞춘다. 일반구 분류가 없으면 상위 시로 대체한다. 광주와 전남은 R-ONE의 "전남광주" 분류로 찾는다.
- 이 통계표에는 지수만 있어 전주 대비 증감률은 지수로 직접 계산한다.
- 지가변동률에 지하철 역세권, 고속철도 역세권, 3기신도시 등 보조지수가 있어 호재 카테고리의 정량 소재로 쓸 수 있다(미사용).

### 3.1 KB부동산 데이터허브 검토 (2026-11-09)

[KB부동산 데이터허브](https://data.kbland.kr/)에서 메뉴 구성과 미분양 화면을 확인했다.

## 4. 경로에서 지역 구하기

### 4.1 SDK 조사 결과 (NaviHelper 3.0.5, navi-data 3.0.4)

| 필요한 정보 | SDK | 결과 |
| --- | --- | --- |
| 현재 위치 | `getCurrentLocationInfo` → 위도, 경도, 주소 | ✅ |
| 목적지 | `getDestinationInfo` → 위도, 경도, 남은 시간(`remainTime`) | ✅ |
| 경유지 | `getWaypointInfo` → 이름, 좌표, `poiId`·`poiProvider`·`poiSubId` | ✅ 좌표가 0으로 올 때가 있음(4.2) |
| 최근 목적지 | `getRecentDestinationInfo` → 좌표, `poiId`·`poiProvider`·`poiSubId` | ✅ 경유지 좌표 복원에 사용 |
| 즐겨찾기 | `getBookmarkInfo` → `HOME`, `OFFICE`, `DEFAULT` 등 | ✅ |
| 안내 시작/종료/취소/도착 | `onRouteStarted`, `onRouteEnded`, `onRouteCancelled`, `onDestinationArrived` | ✅ |
| **경로 선형(좌표열)** | 공개 데이터 클래스에 없음 | ❌ |
| 경로 위 지점 | `TripSummary.routePoints` (좌표, `ratioOnRoute`) | ⚠️ 미검증, 미사용 |

**제약:** SDK가 경로 전체 좌표를 주지 않으므로, 출발 전에 "지나는 시군구 전체"를 알 수는 없다. 그래서 출발지, 경유지, 목적지, 주행 중 현재 위치로 지역을 구한다. 외부 길찾기 API는 쓰지 않는다.

### 4.2 처리 방법

```
출발지(현재 위치), 경유지, 목적지
  → 좌표마다 동시에 V-World getAddress(type=PARCEL) 호출, level4LC 앞 5자리 = 시군구 코드
  → 경로 순서대로 중복 제거
  → [성남시 분당구, 강남구]
주행 중 15초마다 현재 위치 → 마지막 확인 지점에서 2km 이상 움직였으면 시군구 확인
  → 처음 보는 시군구면 그 지역 소식을 받아 방송에 끼워 넣음 ("지금 지나는 {지역} 소식입니다")
```

- **내비 값 받기:** 현재 위치, 목적지, 경유지를 요청하고 1.2초 기다린 뒤 모인 값을 쓴다.
- **경유지 좌표 복원:** 내비가 경유지 좌표를 0으로 줄 때가 있다. 이때는 최근 목적지 목록을 받아(최대 8초 대기) `poiId`, `poiProvider`, `poiSubId`가 모두 같은 항목이 하나뿐일 때만 그 좌표를 쓴다. 이름이나 순서, 주소로 짐작하지 않는다. 복원하지 못한 경유지는 뺀다.
- **저장된 경로 모드:** 출발지와 도착지만 쓰고, 주행 중 지역을 추가하지 않는다.
- **V-World 사용 조건:** 일일 요청은 무제한이지만, 결과를 별도 저장장치나 DB에 저장할 수 없고 실시간으로만 써야 한다. 그래서 변환 결과를 캐시하지 않고 매번 호출한다. 저장 경로도 출발지와 도착지 좌표만 저장한다. ✅ 성남시 수정구 41131, 분당구 41135, 서초구 11650, 수원시 팔달구 41115로 확인했다. 일반구가 있는 시는 `level2`에 "성남시 수정구"처럼 합쳐서 오고 `level3`는 비어 있다. 41135를 실거래가 API에 그대로 넣어 분당구 거래를 받았다.

**지역 이름 표기:** 화면과 음성에 같은 이름을 쓴다(`Region.displayName`). API 조회에는 V-World 원래 이름을 그대로 쓴다.

| 원래 이름 | 표기 |
| --- | --- |
| 서울특별시 강남구, 부산광역시 해운대구 | 서울 강남구, 부산 해운대구 (특별시·광역시의 구는 도시 이름을 붙임) |
| 경기도 성남시 분당구 | 성남 분당구 (일반구가 있는 시는 "시"를 뺌) |
| 경기도 하남시 | 하남시 |
| 세종특별자치시 | 세종 |

**지역 우선순위:** 시간이 부족할 때 남길 순서는 **목적지 → 출발지 → 나머지(경로 순서)**다. 읽는 순서는 경로 순서를 따른다. ❌ 고속도로로 잠깐 스치는 구간을 낮추는 규칙과 체류 거리 기준 정렬은 구현하지 않았다.

> 카카오맵 API 무료 쿼터 정책이 2026-07-21부터 바뀌어, 개발자 계정의 첫 앱에만 제공된다는 공식 안내가 있다. 길찾기 API를 추가하려면 이용 조건을 따로 확인해야 한다.

### 4.3 에뮬레이터 시연 주행

에뮬레이터의 위치는 고정이고 콘솔로 주행해도 내비 값이 변하지 않는다. 그래서 홈의 "시연 주행" 버튼으로 경로를 시간 흐름에 따라 재생한다.

- 내비 안내 중이면 그 경로(현재 위치, 경유지, 목적지)를 쓰고, 출발지부터 목적지까지 직선 위에 약 3km마다, 최대 12개 지점을 찍는다.
- 안내가 없거나 내비 경로에서 시군구를 찾지 못하면 미리 정한 하남(미사역) → 강동(고덕역) → 송파(잠실역) → 강남(삼성역) 경로를 쓴다. 하남은 지수가 오르고 송파·강남은 내리며, 하남에 교통 소식이 있어 비교하기 좋다.
- 18초마다 다음 지점으로 넘어가며 새 시군구의 소식을 끼워 넣는다. 내비 경로를 따를 때는 내비의 남은 시간으로 분량을 맞추고, 미리 정한 경로는 줄이지 않는다.
- 시연 중에는 내비의 도착 이벤트로 방송을 끝내지 않는다. 시연이 끝난 뒤에는 직접 방송을 시작하기 전까지 자동 시작하지 않는다(에뮬레이터 내비가 모의 경로를 계속 다시 시작하기 때문).
- 시연 주행은 실제 내비 위치 갱신이나 실차 주행을 검증하지 않는다.

## 5. 방송 만들기

### 5.1 템플릿 방식 (LLM 미사용)

숫자는 틀리면 안 되고 응답 시간과 비용도 일정해야 하므로, 공공 데이터를 템플릿으로 문장화한다(`Scripts`, `PressReleases`, `Speech`).

읽기 좋게 바꾼다: `153000`(만원) → "15억 3천만 원", `84.97㎡` → "전용 84제곱미터", `-0.03` → "0.03퍼센트 하락했습니다", `’26.11.13.` → "2026년 11월 13일", `→`·`~` → "에서", 괄호 속 설명은 뺀다. 조사는 받침에 맞춘다(숫자 포함).

**방송 구성**

```
안내          부.읽.카입니다. 참고용 정보이며 투자 권유가 아닙니다. 오늘은 {요일} {1부}와 {2부} 소식입니다.
              {경로 안내} 가는 길에 다른 지역에 들어서면 그 지역 소식도 이어서 전해 드립니다.
지역 1        {지역} 소식입니다. 먼저 {1부}입니다. {소식} 이어서 {2부}입니다. {소식}
지역 2        {지역} 소식입니다. 먼저 {1부}입니다. ... (이 지역에 없는 카테고리: "{지역}에는 이번 주 새 소식이 없습니다.")
(주행 중)     지금 지나는 {지역} 소식입니다. 먼저 {1부}입니다. ...
카테고리 안내  {카테고리}는 이번 주 새 소식이 없습니다. / {카테고리}는 소식을 불러오지 못해 건너뜁니다.
출처          출처는 {기관}입니다.
오늘의 핵심    끝으로 오늘의 핵심을 정리해 드립니다. 첫째, {카테고리} 소식입니다. {핵심} ...
              오늘 방송은 여기까지입니다. 안전 운전하시기 바랍니다.
```

- 지역마다 1부와 2부를 이어서 읽는다. "1부 전체 → 2부 전체"가 아니라 "수정구(1부, 2부) → 분당구(1부, 2부)" 순서다.
- 금리처럼 전국 소식이나 시도·전국으로 넓힌 소식은 그 범위에 드는 경로의 첫 지역에서 그 카테고리 순서에 읽는다.
- 카테고리가 하나뿐인 지역은 "{지역} {카테고리} 소식입니다."로 시작한다.
- 주행 중 끼워 넣는 소식은 지금 읽는 지역의 나머지 뒤, 앞서 끼워 넣은 지역 뒤에 들어간다. 그래서 지역 순서와 지역별 1부·2부 묶음이 유지된다.

**경로 안내 문장** (`BriefingBuilder.routeLine`)

| 기준 | 문장 |
| --- | --- |
| 내비 경로 | 내비게이션 경로를 따라 {지역들} 순서로 전해 드립니다. |
| 목적지 없음 | 내비게이션에 목적지가 없어 지금 계신 {지역} 소식을 전해 드립니다. |
| 저장된 경로 | 저장된 {출발}에서 {도착}까지 경로를 따라 {지역들} 순서로 전해 드립니다. |
| 시연 주행 | 시연 주행 경로를 따라 {지역들} 순서로 전해 드립니다. |

내비 경로와 저장된 경로에 지역이 하나뿐이면 "… 경로에 있는 {지역} 소식을 전해 드립니다."로, 5개 이상이면 앞의 3개와 전체 개수로 줄여 말한다. 저장된 경로에는 "가는 길에 …" 문장을 붙이지 않는다.

**소식 원칙 (2026-11-14)**

1. **금주 → 차주:** 이번 주 소식을 먼저 읽고, 다음 주 일정이 이미 나와 있으면 이어서 읽는다.
2. **이전 기간과 비교:** 비교할 숫자가 있으면 증감을 함께 읽는다(3장 표). 실거래 건수는 비교하지 않는다.
3. **끝맺음 정리:** 카테고리마다 핵심 한 문장을 다시 읽는다. 핵심 문장은 소식마다 미리 만들어 두고, 우선순위가 가장 높은(목적지에 가까운) 지역의 것을 고른다. 정리에 드는 시간은 시간 맞추기 전에 먼저 떼어 둔다.
4. **본문은 자세히, 정리는 짧게:** 소식마다 숫자와 맥락을 함께 읽고, 끝맺음 정리만 한 문장씩 짧게 한다.
5. **말투:** 방송 문장은 모두 "~입니다/~합니다"로 끝낸다. 보도자료의 "~한다/~했다"는 바꿔 읽고, 제목은 "~ 소식입니다"로 감싼다. 화면 안내 문구는 "~해요"를 쓴다.
6. **시작 안내:** 어느 경로 기준으로 어느 지역을 어떤 순서로 읽는지 말한다.

### 5.2 시간에 맞추기

- 내비가 목적지까지 남은 시간을 줄 때만 줄인다. 저장된 경로와 미리 정한 시연 경로는 남은 시간을 모르므로 전부 읽는다.
- 예산 = 목적지까지 남은 시간(`remainTime`) − 끝맺음 정리에 드는 시간 − 여유 30초.
- 소식 길이는 글자 수로 추정한다. 엔진 속도는 초당 6.5자로 잡고(실차에서 보정 필요), 0.9배 속도로 읽으므로 초당 5.85자로 계산한다.
- 예산을 넘으면 우선순위가 가장 낮은 지역의 소식부터 하나씩 뺀다. 우선순위가 같으면 뒤의 것부터 빼서 지역의 첫 소식이 남게 한다.
- 안내, 공통(전국·시도) 소식, 지역 소식 없음 안내, 카테고리 안내, 출처, 끝맺음은 빼지 않는다.
- 주행 중 끼워 넣는 소식은 시간 맞추기를 다시 하지 않는다.

### 5.3 소식이 없거나 불러오지 못했을 때

| 경우 | 안내 |
| --- | --- |
| 분양·청약이 경로 전체에 없음 | 도착지 시도로 넓혀 "경로 지역에는 이번 주와 다음 주 공고가 없어 {시도} 소식을 전합니다." |
| 보도자료가 경로 시군구에 없음 | 시도·수도권으로 넓히고, 그래도 없으면 전국 최신 2건 |
| 다른 지역에는 있는 카테고리가 이 지역에 없음 | "{지역}에는 이번 주 새 소식이 없습니다." |
| 이 지역에 모든 카테고리가 없음 | "{지역}에는 {카테고리}의 이번 주 새 지역 소식이 없습니다." 조회에 실패한 카테고리는 "{지역}의 {카테고리} 소식을 불러오지 못했습니다." |
| 카테고리 전체가 없음 | "{카테고리}는 이번 주 새 소식이 없습니다." |
| 카테고리 조회 실패 | "{카테고리}는 소식을 불러오지 못해 건너뜁니다." 다른 카테고리는 그대로 읽는다 |
| 주행 중 지역의 조회 실패 | "{지역}의 {카테고리} 소식을 불러오지 못해 건너뜁니다." |

❌ API가 실패했을 때 저장해 둔 최근 데이터를 읽는 기능은 없다. 기기에 소식을 저장하지 않는다(6장 불러오기의 메모리 캐시만 있음).

## 6. 음성과 오디오

- **TTS:** Pleos `TextToSpeech` 3.3.1, `Mode.ON_DEVICE`, `ko-KR`. 앱 등록과 네트워크가 필요 없다. 오디오 존 0번, `USAGE_MEDIA` + `CONTENT_TYPE_SPEECH`로 재생한다. 한 번에 한 문장씩 보낸다. ✅ 에뮬레이터에서 재생 확인.
- **속도:** SDK 3.3.1에는 말하기 속도 설정이 없다. 문장마다 그 문장을 읽는 시간의 약 11%(0.3~1.2초)를 쉬어 전체가 0.9배 속도로 흐르게 한다. 시간 맞추기의 글자 수 추정도 같은 비율을 쓴다.
- **불러오기:** R-ONE은 요청마다 5~8초가 걸린다. 그래서 카테고리, 지역, 좌표별 요청을 동시에 보내고, 앱을 켤 때 경로와 상관없는 목록(R-ONE 지역 분류, 보도자료 목록)을 미리 받는다. 보도자료 목록과 R-ONE 지수는 메모리에 1시간, 보도자료 본문과 주택형 정보는 앱이 켜져 있는 동안 다시 쓴다.
- **오디오 포커스:** 재생 전에 `USAGE_MEDIA`, `AUDIOFOCUS_GAIN_TRANSIENT_MAY_DUCK`, `setWillPauseWhenDucked(true)`로 요청한다. 값은 코드에 고정했다.
- **내비 안내와 겹칠 때:** 소리를 낮춰 겹치게 하지 않고 멈춘 뒤, 포커스가 돌아오면 그 문장 처음부터 이어 읽는다. 숫자를 놓치면 소식의 의미가 없어지기 때문이다.
- **다른 미디어가 재생 중일 때:** 직접 재생을 누르면 포커스를 빼앗지 않고 "다른 오디오가 재생 중이에요. 일시정지한 뒤 재생해 주세요"라고 안내한다. 자동 시작은 최대 30초 기다린다(2.3). 포커스를 아예 잃으면 멈추고, 다시 들으려면 재생을 눌러야 한다.
- **전원:** 차량 전원 정책(`CarPowerManager`)에서 오디오가 꺼지거나 화면이 꺼지면 멈추고, 돌아오면 이어 읽는다.

## 7. 화면

Pleos 디자인 시스템(색, 타이포, 여백, 컴포넌트)과 Asta Sans 서체를 쓴다. 카테고리마다 클레이 그림과 파스텔 색이 있다. 방향을 고정하지 않아 내비 옆 1/3 분할 창(세로)에서도 쓸 수 있다. 분할은 사용자가 창 막대를 끌어서 하며, 앱이 강제할 수 없다.

| 화면 | 구성 |
| --- | --- |
| 위치 동의 | 처음 시작할 때 "내 경로의 소식을 들으려면": 차량 위치로 시군구만 확인하고 저장하지 않는다는 안내, "동의하고 시작" |
| 홈 | "{요일}요일 부동산 라디오", 듣기 범위, 1부·2부 카드, 오늘 경로 지역 칩, "오늘 방송 듣기", 이번 주 편성 줄과 "시연 주행". 주말에는 카테고리 10개 |
| 방송 중 | "방송 중 · {1부/2부} · {카테고리}", "지금 {지역} 소식", 지금 읽는 문장, 내 경로(최대 6개 지역, 지금 듣는 지역 표시), 처음부터 / 재생·일시정지 / 다음, 끝내기 |
| 편성표 | 월~금 × 2칸과 소식 박스 10개. 끌어서 놓기, 바꾸기, 빼기 |
| 설정 | 어디의 소식을 들을까요(내 경로 지역 / 저장된 경로 + 경로 선택), 언제 시작할까요(자동 시작), 데이터 출처, 면책 문구 |

### 7.1 Pleos 설계 가이드 반영

| 가이드 | 반영 |
| --- | --- |
| 앱 카테고리 | **Music/Audio**(오디오북형). 주행 중 청취와 재생, 일시정지, 다음 같은 단순 조작이 허용 범위 |
| 주행 규제 | ✅ `CarUxRestrictionsManager` 기준. `NO_SETUP`이면 편성표와 설정 버튼을 잠그고 "주행 중에는 편성표와 설정을 열 수 없어요"를 띄운다. `LIMIT_CONTENT`·`LIMIT_STRING_LENGTH`이면 문장을 숨기고 "주행 중에는 소리로만 들려드려요"를 보인다. `distractionOptimized` 선언 |

| 전원 | ✅ `android.car.permission.READ_CAR_POWER_POLICY`로 오디오 전원 정책을 받는다 |

| 개인정보 | ✅ 첫 실행에서 위치를 쓰는 이유를 안내하고 동의를 받는다. 위치를 로그에 남기지 않는다 |

## 8. 앱 구조

Kotlin + Jetpack Compose, 서버 없이 기기에서 공공 API를 직접 호출한다.

```
app/src/main/java/ai/bureadcar/app/
  model/     Category, ListenMode, Place, SavedRoute, RouteBasis, Region, Segment
  schedule/  WeeklySchedule(기본 편성), SettingsStore(편성·설정·저장 경로)
  route/     NaviSource(내비, 시연 경로), UxRestrictionSource(주행 규제), AudioPowerSource(전원)
  data/      Providers(카테고리별 NewsProvider, BriefingBuilder), PressReleases(보도자료),
             Scripts(문장 템플릿), VWorldGeocoder, Http, ApiResponses
  briefing/  BriefingPlan(시간 맞추기, 끝맺음, 속도), PlaybackQueue(재생 위치, 끼워 넣기), Speech(숫자·조사·말투)
  player/    BriefingPlayer(TTS, 오디오 포커스, 문장 사이 쉼)
  ui/        RadioViewModel, App(홈), NowPlaying, ScheduleBoard, SettingsScreen, Components, Theme, PleosIcons
```

```kotlin
enum class ListenMode { ON_ROUTE, SAVED_ROUTE }

data class Region(val lawdCode: String, val sido: String, val sigungu: String) {
    val displayName: String // 화면과 음성의 이름 (4.2)
}
data class SavedRoute(val id: String, val name: String, val origin: Place, val destination: Place) // 지역은 V-World 조건상 저장하지 않음
data class WeeklySchedule(val days: Map<DayOfWeek, List<Category?>>) // 요일당 2칸, 빈 칸은 null

interface NewsProvider {
    val category: Category
    val source: String
    val regional: Boolean // false면 전국 소식(금리)
    suspend fun fetch(regions: List<Region>, today: LocalDate): List<RegionNews>
    suspend fun warmUp(today: LocalDate) {} // 경로와 상관없는 목록 미리 받기
}

data class RegionNews(
    val region: Region?,       // 시도·전국 소식은 null
    val text: String,
    val isSample: Boolean = false,
    val highlight: String? = null, // 끝맺음 정리 문장
    val area: String? = null,      // region이 null일 때 "서울", "수도권", "전국"
)

data class Segment(            // 재생 단위
    val title: String, val text: String,
    val priority: Int? = null, // 작을수록 오래 남음, null은 빼지 않음
    val isSample: Boolean = false, val region: String? = null,
    val highlight: String? = null, val passing: Boolean = false,
)
```

**키:** `local.properties`의 키를 `BuildConfig`로 넣는다. 심사 환경 재현을 위해 지금은 `local.properties`를 저장소에 포함했다. 앱이 API를 직접 부르므로 APK에도 키가 들어간다.

**제품화할 때**는 프록시 서버가 필요하다. APK에 들어간 키는 추출될 수 있고, 차량마다 같은 데이터를 호출하는 낭비가 있으며, 신고가 판정에 쓸 과거 데이터와 실패 대비 저장 데이터도 서버에 쌓는 편이 낫다. `NewsProvider`만 바꾸면 전환되도록 나눠 두었다.

**테스트:** JVM 단위 테스트 67개(`BriefingBuilderTest`, `CoreLogicTest`, `PressReleasesTest`). 방송 순서, 시간 맞추기, 문장 변환, 보도자료 분류와 본문 읽기 등을 검사한다.

## 9. 법적 고지와 안내

- 방송 첫머리와 설정 화면에서 "참고용 정보이며 투자 권유가 아닙니다"를 안내한다.
- 음성에서 "지금이 기회" 같은 평가나 매수·매도 권유를 하지 않는다. 사실, 수치, 기준일, 출처만 읽는다.
- "호재"는 보도자료 원문의 사업 단계를 그대로 읽는다. 계획 단계 사업을 확정처럼 들리게 바꾸지 않는다.
- 언론 기사는 쓰지 않는다. 공공누리로 공개된 국토교통부 보도자료의 제목과 본문 첫 문장만 읽는다.
- 공공 API별 이용 조건(출처 표시, 상업적 이용)을 지킨다. 방송 끝에 출처를 읽는다.
- 위치와 경로는 기기에만 저장하고, 지역 변환에는 필요한 좌표만 보낸다.
